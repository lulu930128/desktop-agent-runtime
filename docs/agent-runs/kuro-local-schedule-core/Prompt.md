# Kuro 本機時間表需求規格

2026-09-12。使用者先批准 M0–M3，後續批准完成 M4–M6 並可重開桌寵測試。目前交付與限制見 Progress.md。

## 目標與已確認需求

建立 Kuro Core 保存的本機排程系統，支援手動安排、待辦期限、學習計畫、自訂固定行程與單次特殊行程；跨多日仍在持續的安排包含在今日。每個排程可獨立選擇是否通知。

使用者已同意強化外部同步完整性、事件版本與移除語意；外部帳號與權限後續另行處理。本機提供資源可以使用，仍保留私人資料不進 Git 的邊界。

本規格調整附件以 Google Calendar 為第一步的順序。附件是參考提案，不是執行授權。先做本機時間表，Google Calendar 留後續 integration。

## 第一版交付

- 單次與重複排程新增、編輯、取消；固定系列與單次例外。
- 一般行程、學習安排、待辦期限三種類型。
- 全天、跨日、時區、完成追蹤與逾期展示。
- 今日／未來七日清單、日期選擇、編輯表單。
- Core persistence、service、Launcher lifecycle、Electron transport。
- 個別通知、去重、稍後提醒、勿擾與配送紀錄。
- Mail／Study／Chat 相容性；Calendar legacy ownership 退出。

## 延後範圍

- AI 自動排程、自動拆課、衝突自動改期。
- 月曆拖拉、跨裝置、多使用者、語音提醒。
- 全面遷移 Mail／Study／OMI，或完整通用 Task／Policy／Action 平台。
- commit、push、發布、修改 Codex 長期記憶。

## 待審核預設

以下建議已作為本批實作預設；尚未實作的 UI／配送預設可在後續複查調整：

1. 重複規則先支援每天、每週指定星期、每月指定日期；可設間隔、截止日期或次數。不存在的月日期跳過。
2. 系列編輯支援「只改這次」「這次及以後」「整個系列」。
3. 一般行程預設不追蹤完成；學習安排與待辦預設追蹤完成，建立時可設定。
4. 新排程預設不通知；啟用時預設提前 10 分鐘，支援準時提醒。第一版每個項目一個提醒時間。
5. 全天提醒預設當日 09:00；勿擾預設 22:00–08:00，可修改或停用。
6. 通知渠道先做面板與桌面。稍後提醒提供 10 分鐘、30 分鐘、自訂時間。
7. 初始時區取本機設定並正規化為 IANA timezone；系列保存自己的時區，不隨機器變更靜默改動。
8. 第一版採今日／七日清單與日期選擇，暫不做月曆格。

## 完成條件

- 使用者可建立、編輯、取消、完成適用項目，重啟後狀態一致。
- 重複規則及單次例外不產生重複項目，不污染其他 occurrence。
- 跨日／全天／逾期／完成符合 Plan.md。
- 通知停用、勿擾、完成、取消、修改後不發送舊提醒。
- Mail refresh 不覆蓋本機排程；Core unavailable 不顯示假空清單。
- Source/tests、正式 runtime、產品操作驗收分開記錄，必要門檻全通過才稱第一版完成。
