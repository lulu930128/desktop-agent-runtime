# Kuro 工具分析與簡短口播任務規格

狀態：實作與後端驗證完成；正式 Qt／LLM 重啟採用及使用者聽感仍待確認。日期：2026-11-05（Asia/Taipei）。

執行授權更新：使用者已同意實作及真實 API 反覆測試，上限 150 次；並接受先用純後端驗證，不以開啟 Qt 視窗作為測試前置條件。下方桌面驗收仍是長期產品終點，不能把後端合成證據寫成正式 Qt 全流程驗收。

## 最終目標

使用者能在正式 Qt Chat 要求 Kuro 使用 OMI，或讀取授權範圍內的電腦／程式資料。Kuro 實際取得工具證據後，在畫面保留完整分析，並透過目前角色聲音說出簡短、有內容、忠於證據的回答；不朗讀路徑、URL、程式碼或原始 log，也不因自然語言表達不同而整段無聲。

成功必須涵蓋「工具確實執行 → 結果正確呈現 → 口播簡潔 → 中央合成成功 → 桌寵實際播放 → 使用者聽感確認」。只有文字完成、TTS HTTP 200、WS 已送出或測試通過，都不足以單獨宣告完成。

## 預期體驗

- 一般分析預設 2～3 句：結論、會影響判斷的限制、至多一個下一步。簡單問答可少於兩句，不為填格式增加廢話。
- 短口播目標約 10～25 秒；這是待實測校準的產品目標，不是目前效能。超過 35 秒須檢查是否冗長；必要風險說明可保留並記錄原因，禁止硬截字或截音訊。
- 完整路徑、URL、來源連結、程式碼、命令、表格、stack trace、工具名稱清單留在 Qt 文字／History；口播用「設定檔」「登入流程」「來源文件」等有意義的描述。
- 技術名稱如 Python、Node.js、OMI 可以自然提及；數字、錯誤碼或函式名稱只有在理解結論確有必要時才說。讀檔位置仍在畫面可查。
- 保留目前角色與日文語音設定；本文的中文示例說明語意，不代表切換語音語言。對話文字維持既有語言政策。
- 使用者明確要求詳細解說時才展開，仍不逐字朗讀技術 payload。

| 場景 | 畫面應保留 | 短口播的語意示例（非固定模板） |
| --- | --- | --- |
| 查 OMI 能力與新鮮度 | 真實查詢結果、能力範圍、時間、partial／unknown、來源 | 「已查到 OMI 的研究能力，但行情完整度仍有限。可以先選一檔股票，再確認它的資料日期與缺漏。」 |
| 查詢一檔股票 | OMI 提供的結構化證據、重要數值及限制 | 「這檔股票的技術與籌碼資料可以查看，不過部分資料尚未確認。現在適合先補齊證據，再討論結論。」僅在當次證據支持時使用此意義。 |
| 檢查程式問題 | 檔案位置、行號、問題片段、修正建議、驗證範圍 | 「問題出在錯誤處理：請求失敗後仍被當成成功。建議先區分失敗狀態；位置和修改方式已列在畫面上。」 |
| 來源無法取得 | 失敗類型、已完成與未完成範圍 | 「這次沒有取得來源資料，還不能確認原因。畫面上有失敗位置與下一個檢查步驟。」 |

固定說「請看畫面」、只有提示音、只讀打招呼、只播失敗通知，均不算分析口播成功。

## 邊界與限制

1. OMI 擁有市場資料、freshness 與分析決策；Kuro 消費證據並做呈現，不在 prompt、Qt 或 Pet 重做市場判斷。不把工具可見／connected 當成查詢成功。
2. 電腦／程式場景只讀取授權來源；分析程式不代表自動修改 repo、執行檔內命令、啟停服務或寫入外部系統。沿用 tool policy。
3. Conversation runtime 擁有語音呈現政策與工作佇列；Qt 擁有應用介面；Pet 擁有音訊播放與 Live2D；中央 Voice Runtime 擁有模型與推論。
4. 文字不因口播縮短而丟失。Private speech footer 不進公開文字、History、Memory 或 tool arguments。
5. 保留會改變結論的失敗、未知、資料不足、否定、前提與關鍵數值。不能只為了有聲音而取消全部檢查，也不能把字詞比對不到當成已證明矛盾。
6. 正常路徑沿用主回應同時生成 Display／Speech；不每回合額外呼叫翻譯或語意裁判。僅失敗時的一次有界修復列入計畫，另記成本、耗時與結果。
7. 保留大量既有 dirty WIP、index 與原計畫；使用者已授權局部實作與測試。保存 task-only preimage、正式資產備份及可回退 release pin，不 commit／push。
8. 原始對話、工具 payload、音訊、私有路徑與 secrets 不進任務文件或 Git；重現資料用匿名 synthetic fixtures，實機證據留本機受控位置。

## 非目標

- 本輪不升級模型、替換音色、引進另一套語音框架或第二個中央引擎。
- 真正串流合成與 LLM 增量語音是後續效能項目，並非本次可靠口播的前置條件。
- 不保證跨語語意可由 deterministic 程式完全證明；測試、狀態與聽感驗收必須如實保留這項限制。
- 不擴充 OMI provider、強制刷新市場資料、生成持久化投資報告或執行交易。

## 交付與完成條件

- 實作與測試依 [Plan.md](Plan.md) 推進；進度與驗證記入 [Progress.md](Progress.md)。
- 所有強制回歸案例通過，含自然日文改述、否定、重要限制、路徑／URL、missing、busy、播放失敗及取消。
- 正式 runtime 完成六類場景各兩次的驗收；12 次皆有實質口播、零路徑／URL／code 洩漏、零已發現的關鍵事實反轉。修復成功與首次成功分開統計；固定降級通知不得充數。
- 可控故障有可見原因與有界結束，不冒充播放成功、不污染下一回合。外部來源故障如實回報，不能把工具無法取得證據標成工具成功。
- 使用者確認短口播聽得懂、不冗長、音色正常。最終完成狀態必須是桌面實際驗收通過，不能停在 Source PASS。
